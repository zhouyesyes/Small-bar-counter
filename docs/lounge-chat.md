# 休息区和聊天阅读页

随扩展面板里的「吧台美化」开关启停，小手机保持原有设置。英文大标题沿用其他页面的花体；休息区和聊天正文统一使用其他吧台页面的宋体字体栈。

## 休息区

以角色头像文件名（群聊使用群 ID）将宿主已载入的聊天收在一起，同名角色不会混组。初始每个角色一行，只显示头像、备注名和聊天数量；消息预览只在展开后的具体聊天条目显示，条目同时保留原生的消息条数和文件大小。点开角色行再选择具体对话。每组保持紧凑显示，可展开旧聊天。首页设置的显示数量按角色人数计算，同一角色的多段聊天只算一人；输入 0 显示全部，超出首屏人数用「再看几人」展开，再点「收起」回到设定人数；搜索暂时展示全部匹配角色，清空后恢复原显示状态。

「置顶角色」把该角色放进上方头像区，按数量整组居中；点头像直接进入该角色最新的聊天，旧记录仍保留在下方分组内，点开可查看。它独立于角色卡的常用标记，也独立于宿主对单段聊天的置顶。单段聊天仍可在自己的菜单里置顶或删除，走原生处理流程。角色菜单里的「改名」仅为显示备注，不修改角色卡名、聊天文件名或发给模型的内容；模糊预览只影响休息区。

右上角用线条图标打开首页设置，提供日间/夜间/跟随酒馆、头像背景配色、首页显示人数设置。底部三个带图标的辅助色按钮分别打开酒窖、调酒师、工具；原生临时聊天按钮移到它们下面，保留原来的点击处理；「＋ 新开一桌 · 临时聊天」使用独立的显示文字，避免宿主翻译观察器再次覆盖它。关闭美化会移除新增文字，让原生翻译显示恢复。

按角色收纳、角色置顶头像区与展开操作参考了用户提供的兔兔聊天收纳脚本（其 JSON 指向 L5isa/Chat 的 rabbit-messages.js），没有执行或引入该远程脚本。分组只处理宿主已载入的聊天，未载入记录的范围仍由宿主的加载数量控制。列表下方只保留一个小按钮：有折叠角色时显示「再看 N 人」，N 随剩余人数变化，展开后显示「收起」并可回到人数限制。展开时复用官方入口；若宿主尚有未载入记录但暂时没有可计算的折叠人数，同一个按钮显示「更多聊天」，载入后重新计算人数。按钮采用小字号文字及小箭头，不再另放第二个入口。

## 聊天

标题位于聊天滚动区。每条消息使用 62px 通栏头图、40px 头像和两侧 10px 正文边距，没有卡片背景或边框。自己的头像在右侧，跟随朋友圈；对方跟随角色卡。群聊保留各消息的原角色头像。对话页仅展示这些共用图片，在角色卡或朋友圈原有入口修改后同步更新，旧 `chatAppearance` 独立覆盖不再参与显示。

正文、编辑和切换回复继续使用原生节点与处理，楼层、Token 等统计仍在每条消息末尾。底部输入栏的菜单、魔杖、展开、助手与发送图标统一为辅助色线条样式，保留原生尺寸、点击处理及隐藏/停止状态，不依赖图标字体。流式生成不重建头图或第三方脚本内容。关闭美化会把原生聊天行、临时聊天按钮移回原处，恢复原先的折叠状态和界面。

## 验证

用 TauriTavern 2.4.0 的直接挂载 welcomePanel、原生 welcome.css 和消息模板在 Chromium 390px 下检查：角色分组和展开、旧聊天、角色置顶与单段置顶分离、备注不改原名、搜索、设置及三个快捷按钮的 SVG、底部临时聊天和原生事件、配色入口、宋体正文以及关闭恢复。效果图由这个实际模块生成，随本次对话提供。




## 管理页面的卡片和角色布局

世界书名称、API 模型名与预设名称共用 17px 字号和行高。名称保持单行，过长时可以横向滚动查看，不丢失原始文字。角色名单中的长名字可以完整换行，名单和详情均由外层面板滚动，长内容的末尾可达。

角色详情把原生操作区作为独立的横向工具行放在头像与名字下方；常点、酒单、会员卡、导出、复制和更多按可用宽度横向排列，标签也横向排列。原生控件及点击处理保留，关闭美化时恢复操作区原本的位置。
