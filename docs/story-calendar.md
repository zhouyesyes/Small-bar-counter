# 剧情月历与往月留痕

日历在正常聊天回复及已有的手动状态刷新中维护，不另开定时 API。更新提示会参考当前世界观、已知日期和上一份有效记录；打开或翻页本身不会生成未来剧情。

## 本月记录

每个新剧情月优先整理五个适用的节日、节气、生日或纪念日，再加入已经成立的行程。生日及关系纪念日必须有设定依据；虚构世界若需要补充公共节俗，明确标记「世界补充」，不补造个人过往。普通约会、任务和剧情阶段不作为节日凑数。

所有有记录的日期都画圈，格子下方只显示节日类批注，点开仍可查看该日的普通事件。详情支持时间、地点、具体内容、范围和有依据的同期事件。未兑现的约定保留；过期但未确认的约定显示「到期未确认」，不会自动完成。倒计时按剧情日期或世界观同月日号计算。

沿用青松 WOFF2 分片字体显示批注和详情，日历数字保持原字体，折叠时不下载字体文件。

## 月份与纪年

明确公历日期继续使用 `calendar.date`。非公历使用 `worldDate` 文字日期与 `month={key,label,days,firstWeekday,currentDay}`；`firstWeekday` 从周一 0 到周日 6，没有星期制填 `null`。缺少年份不补现实年份，月长不明时不画虚假的日期格，先显示已有文字日期。

事件支持稳定 `id`、`date` 或 `monthKey/day`、`displayDate`、`name`、`category`、`kind`、`status`、`time`、`location`、`text`、`concurrent`、`scope`、`basis`。老版日期事件自动兼容。新增日期和事件仍依赖聊天模型按规则输出，程序不会自己捏造五个节日。

## 归档

跨入下一剧情月时，程序先将刚结束且有记录的月份整理为月末回顾，普通旧细目退出活动列表；重要已知日期简要保留，未兑现约定继续追踪。聊天模型可通过 `summaries` 改写对应已结束月份的回顾，不能加入未来月份的总结。

累计四个已结束且有记录的月份后，四份月报压成一册回顾；模型可用匹配四个月 key 的 `periodSummaries` 进一步归纳。跳月不补空白剧情，因此按有实际记录的月份累计。压缩后的回顾在「往月留痕」里折叠展示，每册可展开「查看逐日原始记录」，查看该月或四个月的完整记事、时间、地点及同期事件。翻回旧月也能点开有圈日期查看详情。当前月继续保留详情；原始聊天及历史酒卡不删除。

逐日原始记录仅保存在本地重建状态的 `calendar.history`，不会随正常聊天或手动刷新时的连续性参考额外注入 AI；AI 的这份参考只含月报／合订回顾、当前月和未解决约定。酒馆自身仍可能提供上下文范围内的原聊天，这项压缩不删除或隐藏酒馆原文。旧聊天已有的酒杯记录会在重建时恢复原始细目；从未生成或已经删除的原始内容无法凭总结还原。

纯记录整理有长度限制，会均衡保留四个月的内容；它不是额外调用 AI 生成的文学总结。模型的自然文字回顾由本轮或后续回复提供。所有结果由选中的回复重建，删除、重生成或切换回复可恢复对应时间的月历。

验证：`tests/calendar-state.test.mjs` 覆盖合并、归档、四月合订、摘要校验、回滚、未来约定、无星期制、未知月长与跳月；`tests/calendar-journal-runtime.cjs` 覆盖日期格、详情、逾期计划、XSS、归档、原生纪年与移动端；已有字体、酒杯面板与真实宿主入口测试继续回归。
